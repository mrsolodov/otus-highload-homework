# Consul: DNS и проверка доступности веб-узлов

Собрал небольшой стенд с тремя Consul-серверами и двумя Nginx. Клиентские агенты регистрируют оба фронтенда как сервис `portal` и проверяют `/health` раз в две секунды. Запрос `portal.service.consul` выдаёт адреса живых фронтендов. Так можно отказаться от одного плавающего IP и получать адрес веб-портала через DNS.

Для проверки взял два локальных Nginx как веб-узлы, по аналогии с предыдущими стендами. Существующие машины и приложение из ранних работ этот Compose-файл не запускает. Адреса веб-узлов в сети Compose закреплены, чтобы DNS-ответ можно было однозначно сравнить с ожидаемым.

## Запуск

Нужны Docker Engine с Compose v2, Bash и Python 3. Из этого каталога:

```bash
bash scripts/run-lab.sh
```

Скрипт дожидается кворума из трёх голосующих серверов и двух здоровых записей в DNS. Затем останавливает `web2` и проверяет, что его IP исчез из DNS и списка здоровых сервисов. После возврата `web2` снова должны появиться оба адреса. Наконец, скрипт останавливает `consul1` и проверяет, что второй сервер отвечает на DNS-запросы при кворуме из двух узлов. Вывод сохраняется в `evidence/lab-run.txt`.

Стенд прошёл [интеграционную проверку в GitHub Actions](https://github.com/mrsolodov/otus-highload-homework/actions/runs/42002010427). В начале DNS выдавал `172.29.16.11` и `172.29.16.12`; после остановки `web2` остался только `.11`, после запуска `.12` вернулся. При остановленном `consul1` второй сервер продолжил отдавать обе записи. Краткая выписка есть в [`evidence/ci-verification.txt`](evidence/ci-verification.txt), полный вывод — в артефакте запуска.

DNS проверяется прямым UDP-запросом к Consul на порту `18600`, а при остановленном `consul1` — на `18601`. Системный DNS-кеш в проверке не используется. В браузере доступен [Consul UI](http://127.0.0.1:18500/ui/), веб-узлы опубликованы на `127.0.0.1:18081` и `127.0.0.1:18082`.

Для удаления стенда вместе с учебными томами:

```bash
bash scripts/run-lab.sh --destroy
```

Три сервера Consul запущены как отдельные контейнеры на одном Docker-хосте. Проверка отказа одного сервера подтверждает работу кворума в этом стенде, но не защищает от потери всего хоста. Для учебного стенда ACL и TLS не включены, наружу порты открыты только на loopback.

Документация: [кластер из трёх серверов в Docker](https://developer.hashicorp.com/consul/docs/deploy/server/docker), [DNS service discovery](https://developer.hashicorp.com/consul/docs/discover/service/static), [проверки здоровья](https://developer.hashicorp.com/consul/docs/register/health-check/vm).
