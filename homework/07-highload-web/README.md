# Веб-приложение с отказоустойчивыми фронтендами и бэкендами

Для этого ДЗ собрал вариант на локальном стенде Vagrant + VirtualBox. Используются пять ВМ: два Nginx с Keepalived, два Python/uWSGI-бэкенда и один PostgreSQL. Общая статическая страница лежит на GFS2: бэкенды видят один iSCSI-диск, который экспортирует db1.

Это **подготовленный стенд**. В текущей среде нет доступа к вашему VirtualBox, поэтому запуск пяти ВМ и отказоустойчивость ещё не подтверждены. Скрипт проверки создаст файл результатов только после реального запуска; результатов прогона в репозитории сейчас нет.

| ВМ | IP в локальной сети | Роль |
| --- | --- | --- |
| nginx1 | 192.168.56.11 | Nginx, Keepalived; приоритет 110 |
| nginx2 | 192.168.56.12 | Nginx, Keepalived; приоритет 100 |
| app1 | 192.168.56.21 | Python WSGI под uWSGI, GFS2 |
| app2 | 192.168.56.22 | Python WSGI под uWSGI, GFS2 |
| db1 | 192.168.56.30 | PostgreSQL, iSCSI target, третий голос Corosync |

Общий IP фронтендов — 192.168.56.100. Nginx пересылает запросы двум бэкендам. Адрес /health записывает запрос в PostgreSQL и возвращает имя узла; /static/index.html читается с общего GFS2-диска. Keepalived проверяет /health на локальном Nginx и передаёт общий IP второму фронтенду при отказе первого.

## Запуск

Нужны Windows с VirtualBox и Vagrant, а также WSL с Ubuntu и установленным Ansible. Это тот же набор инструментов, что использовался для предыдущего локального ДЗ. В PowerShell:

    Set-Location "D:\Projects\otus-highload-homework\homework\07-highload-web"
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\run-local-lab.ps1"

Скрипт поднимает ВМ, копирует ключи Vagrant в домашнюю папку WSL, определяет доступный из WSL адрес SSH, генерирует локальный пароль PostgreSQL и запускает Ansible. Ключи и пароль не попадают в Git. После успешной проверки скрипт удаляет все пять ВМ. При ошибке ВМ остаются для диагностики; затем их можно удалить командой vagrant destroy -f.

## Проверка

Скрипт запрашивает общий IP, проверяет PostgreSQL, статическую страницу и GFS2 на обоих бэкендах. Затем останавливает сервис приложения на app1 и ждёт ответы только от app2. После восстановления приложения останавливает Nginx на nginx1 и проверяет, что общий IP отвечает через nginx2. Результат записывается в evidence/local-lab-results.json. Это файл локального запуска: до проверки его не следует добавлять в коммит.

Для ручного осмотра стенда без автоматического удаления можно запустить .\run-local-lab.ps1 -KeepVms. После этого проверить vagrant status и удалить стенд через vagrant destroy -f.

## Ограничение

В этой учебной конфигурации у GFS2 нет механизма fencing. При сетевом разделении кластера это опасно для общего диска, поэтому такой вариант не подходит для эксплуатации вне изолированного лабораторного стенда. db1 является единственной точкой отказа для БД и iSCSI. По критерию ДЗ проверяется отказ одного фронтенда или бэкенда, а не отказ БД.
