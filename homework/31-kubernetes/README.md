# Kubernetes: веб-портал на двух ВМ

Взял две Ubuntu ВМ из [задания 19](../19-proxmox/) и развернул на них K3s: `172.28.19.10` — управляющий узел, `172.28.19.11` — рабочий. Страницу портала отдают два экземпляра Nginx, по одному на каждой ВМ. Traefik направляет к ним запросы через Ingress.

## Запуск

Нужны работающие ВМ, SSH-ключ пользователя `ubuntu`, право `sudo` без пароля и доступ ВМ в Интернет. Из этого каталога в PowerShell:

```powershell
$env:PORTAL_PASSWORD = Read-Host 'Пароль портала'
.\deploy.ps1 -SshKey "$HOME\.ssh\id_ed25519"
Remove-Item Env:PORTAL_PASSWORD
```

Скрипт устанавливает K3s на обеих ВМ, применяет [манифесты](manifests/) и проверяет портал. В них описаны Namespace, ConfigMap, Deployment с двумя репликами, Service и Ingress. Secret с хешем пароля создаётся при запуске (Git не попадает). Системный Nginx из задания 23 скрипт останавливает, чтобы освободить порт 80. Повторное применение Salt может вернуть прежние настройки Nginx и iptables.

Для браузера необходимо добавить в Windows `hosts` строку `172.28.19.10 portal.otus.test` и открыть `http://portal.otus.test/`. Логин — `otus`, пароль — тот, который задали при запуске. Проверить доступность без записи в `hosts` можно так:

```powershell
curl.exe -H 'Host: portal.otus.test' http://172.28.19.10/health
```

На этом стенде DNS внутри ВМ работает нестабильно. Перед установкой скрипт получает адреса нужных репозитриев через DNS Windows и добавляет их в `/etc/hosts` ВМ.

## Проверка и бэкап

На управляющей ВМ:

```bash
sudo kubectl get nodes -o wide
sudo kubectl -n otus-portal get deployment,pods,service,ingress -o wide
sudo systemctl status otus-k3s-backup.timer
```

Таймер каждый день в 03:00 по времени ВМ сохраняет YAML ресурсов, базу SQLite, конфигурацию K3s и серверный токен в `/var/backups/otus-k3s`. Первую копию `deploy.ps1` забирает на Windows и проверяет по SHA-256; следующие можно забрать командой `.\fetch-backup.ps1`. Архив содержит секреты, поэтому каталог `backups/` исключён из Git. Для восстановления нужны и база, и токен; порядок описан в [документации K3s](https://docs.k3s.io/datastore/backup-restore).

## Что получилось

Оба узла имеют состояние `Ready` а два pod портала работают на разных ВМ. Через оба адреса Ingress `/health` отвечает `200`; главная страница с паролем — `200`, без пароля — `401`. Ежедневный бэкап включён, первая копия сохранена вне ВМ и проверена. [Вывод проверки](evidence/cluster-verification.txt) лежит рядом с конфигурацией. Пароль этого запуска сохранён только в локальном `portal.secret`, который исключён из Git.
