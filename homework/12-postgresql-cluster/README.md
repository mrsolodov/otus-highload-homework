# Кластер PostgreSQL с Patroni

Для этого задания я собрал три узла PostgreSQL 16 под управлением Patroni. Состояние кластера хранится в etcd из трёх узлов, а HAProxy направляет подключения для записи только на текущий primary. Выбор узла HAProxy делает по ответу Patroni `/primary`, поэтому после смены лидера адрес для клиента остаётся прежним.

## Запуск

Нужны Docker Engine с Compose v2, Bash, OpenSSL и свободные ресурсы для семи контейнеров. Из этого каталога:

```bash
bash scripts/run-lab.sh
```

При первом запуске скрипт создаёт локальный `.env` с двумя случайными паролями. Он не отслеживается Git. Контейнеры и данные после проверки остаются на месте. HAProxy доступен только на `127.0.0.1:15432`; порты PostgreSQL, Patroni и etcd наружу не опубликованы.

Чтобы остановить стенд и удалить учебные данные после проверки:

```bash
bash scripts/run-lab.sh --destroy
```

Если проверка прервалась, состояние можно посмотреть через `docker compose ps` и `docker compose logs`. Для ручной очистки из этого каталога используется `docker compose down -v` — эта команда удаляет тома с данными задания.

## Что проверяет скрипт

1. Три узла готовы, один из них primary, два работают как реплики.
2. Запись через HAProxy видна на всех узлах.
3. После остановки текущего primary Patroni выбирает новый, а HAProxy принимает вторую запись через тот же адрес.
4. Остановленный узел возвращается как реплика и видит обе записи.
5. Все три endpoint etcd отвечают на проверку здоровья.

Результат записывается в `evidence/cluster-check.txt` и прикладывается к запуску GitHub Actions как артефакт. При ошибке скрипт завершается с ненулевым кодом; контейнеры остаются для диагностики. Все семь контейнеров запускаются на одном Docker-хосте, поэтому проверка отказа узла не означает устойчивость к потере самого хоста. В учебном стенде внутренний трафик также идёт без TLS.

Проверка [прошла в GitHub Actions](https://github.com/mrsolodov/otus-highload-homework/actions/runs/41020981925). В этом запуске `pg3` был первым primary, после его остановки лидером стал `pg2`; две записи прочитались на всех узлах после возврата `pg3`. Краткий [вывод скрипта](evidence/cluster-check.txt) сохранён рядом с конфигурацией.

Опирался на [документацию Patroni](https://patroni.readthedocs.io/en/latest/) и [инструкцию etcd по статической конфигурации кластера](https://etcd.io/docs/v3.5/op-guide/clustering/).
